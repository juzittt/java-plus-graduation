# Explore With Me (Микросервисная архитектура)

Данный проект представляет собой рефакторинг монолитного приложения "Explore With Me" в полноценную микросервисную архитектуру. Приложение позволяет пользователям создавать события, управлять категориями, формировать подборки событий, оставлять заявки на участие и отслеживать статистику просмотров.

## Архитектура проекта

Проект разделен на независимые сервисы, каждый из которых отвечает за свою предметную область и имеет собственную базу данных (паттерн **Database-per-Service**). Взаимодействие между сервисами осуществляется синхронно через REST API с использованием **Spring Cloud OpenFeign**.

### Инфраструктурные сервисы:
1. **Discovery Server (Eureka)** (`infra/discovery-server`): Реестр сервисов. Все микросервисы регистрируются здесь при запуске для обнаружения друг друга.
2. **Config Server** (`infra/config-server`): Централизованный сервер конфигураций. Работает в профиле `native`, читая файлы из локальной файловой системы.
3. **API Gateway** (`infra/gateway-server`): Единая точка входа для всех внешних клиентских запросов (порт `8080`). Маршрутизирует трафик к нужным микросервисам на основе путей (Path).

### Бизнес-сервисы (расположены в директории `core/` и `stats/`):
1. **user-service**: Управление пользователями (создание, поиск, удаление).
2. **category-service**: Управление категориями событий.
3. **event-service**: Управление событиями (создание, редактирование, публикация, поиск). Является основным оркестратором, обращающимся к другим сервисам для валидации данных.
4. **request-service**: Управление заявками на участие в событиях (создание, подтверждение, отклонение инициатором).
5. **compilation-service**: Управление подборками событий.
6. **stats-server**: Сервис сбора и отдачи статистики просмотров событий.

## Управление конфигурациями

Все конфигурационные файлы вынесены из кода сервисов и хранятся централизованно в репозитории по пути:
**`infra/config-repo/`**

Структура директории конфигураций:
- `infra/config-repo/core/` — конфигурации для бизнес-сервисов (`user-service.yml`, `event-service.yml`, `request-service.yml`, `category-service.yml` и `compilation-service.yml`).
- `infra/config-repo/infra/` — конфигурации для инфраструктурных сервисов (`gateway-server.yml`).
- `infra/config-repo/stats/` — конфигурация для сервиса статистики (`stats-server.yml`).
- `infra/config-repo/application.yml` — общие настройки для всех сервисов.

При запуске каждый сервис обращается к `config-server`, чтобы получить свои настройки перед инициализацией контекста Spring.

## Внутренний API (Взаимодействие сервисов)

Для обмена данными между микросервисами используются Feign-клиенты. Ниже приведена матрица внутренних вызовов:

| Клиент (Кто вызывает) | Провайдер (Кого вызывает) | Метод и Эндпоинт | Назначение |
| :--- | :--- | :--- | :--- |
| **event-service** | `user-service` | `GET /admin/users/{userId}` | Валидация существования пользователя-инициатора при создании события. |
| **event-service** | `category-service` | `GET /categories/{catId}` | Валидация существования категории при создании/обновлении события. |
| **event-service** | `request-service` | `GET /internal/requests/confirmed-counts?eventIds={ids}` | **Batch-запрос** для получения количества подтвержденных заявок по списку событий. Решает проблему N+1 при поиске событий. |
| **request-service** | `event-service` | `GET /internal/events/{id}/status` | Получение статуса события, лимита участников и флага модерации для валидации перед созданием заявки. |
| **compilation-service** | `event-service` | `GET /internal/events/by-ids?ids={ids}` | **Batch-запрос** для получения полных данных о событиях, включенных в подборку. |
| **Все бизнес-сервисы** | `stats-server` | `POST /hit` | Отправка информации о просмотре события или списка событий для накопления статистики. |

> *Эндпоинты с префиксом `/internal/` не маршрутизируются через API Gateway и доступны только для межсервисного взаимодействия внутри сети.*

## Внешний API

Все внешние запросы от клиентов (например, Postman-коллекции или фронтенда) должны отправляться на **API Gateway** (`http://localhost:8080`). Gateway автоматически перенаправляет их в соответствующие микросервисы.

## Как запустить проект

Рекомендуемый способ запуска — использование Docker Compose, который автоматически поднимет базы данных PostgreSQL для каждого сервиса и запустит все приложения в правильном порядке.

1. Убедитесь, что у вас установлены **Docker** и **Docker Compose**.
2. Перейдите в корневую директорию проекта.
3. Выполните команду:
   ```bash
   docker-compose up --build
   ```
4. После завершения сборки и старта всех контейнеров, API Gateway будет доступен по адресу: http://localhost:8080
5. Панель управления Eureka Server (для проверки регистрации сервисов): http://localhost:8761

> *(Для локальной разработки без Docker необходимо запускать сервисы в строгом порядке: discovery-server → config-server → остальные сервисы).*
